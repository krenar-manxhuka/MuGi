# Examples — verbatim Sonnet output

These are **unedited** artifacts generated by `claude-sonnet-4-6` during the
benchmark run on 2026-06-21 (`go run ./cmd/bench`). They are kept here to make
the harness's core claim concrete: artifacts are **compiled and tested**, so the
eval catches real bugs — including ones the LLM reviewer approved.

Each example is its own Go module, so it is isolated from the root module and
from `go build ./...` / `go test ./...` at the repo root. Run them directly.

## `url-shortener/` — passed

Sonnet's In-Memory URL Shortener. Builds and passes its own tests; reviewer
approved it 9/10.

```bash
cd examples/url-shortener && go test ./...   # ok — PASS
```

## `expr-eval/` — built, but `go test` caught a bug

Sonnet's Arithmetic Expression Evaluator. It **compiles**, and the reviewer
**approved it at 9/10** with the build/test output in front of it — but its own
tests fail: `-1 * -1` is evaluated to `1` instead of being rejected per the
task's contract.

```bash
cd examples/expr-eval && go test ./...       # FAIL — Eval("-1 * -1")
```

This is the eval thesis in miniature: a capable model produces plausible,
review-approved Go that only execution reveals as wrong. Full captured output
for every task and provider is in
[`../bench/results/RESULTS.md`](../bench/results/RESULTS.md).
